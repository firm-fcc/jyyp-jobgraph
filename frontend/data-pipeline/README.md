# 图谱数据接入层

前端与算法侧的接缝。算法侧是一套离线管线，产出按时间窗口组织的静态 JSON；
本目录的构建脚本将其转换为前端直读的紧凑格式，输出至 `public/data/`。

## 运行

原文表体量在六吉字节量级，单独由 `jdraw.mjs` 先行聚合成中间件，再由 `build.mjs` 透传。
`jdraw.mjs` 在同一次扫描内另产出学历门槛与能力要求的句级归因两项，见下文口径一节：

两条命令均在 `frontend/` 下运行：

```
node data-pipeline/jdraw.mjs --src <算法产出目录>      # 产出 <src>/jdraw.json，约一小时
node data-pipeline/build.mjs --src <算法产出目录>      # 读入上一步的中间件
```

`--src` 缺省指向仓库同级的 `Reference-tmp/graph-2022-05_10(1)/graph-2022-05_10`，
亦可由环境变量 `GRAPH_SRC` 指定。目录布局须为 `graph/{窗口}/{base,delta,effective}/`、
`jd-summaries/jd_summary_{窗口}.csv` 与 `timeline/jd/{窗口}.csv`。

数据包内的布局与此不同：汇总表在 `data/graph/data/` 下，需另行移到 `jd-summaries/`；
结转窗须移出 `graph/`，否则窗口列表会多出两个无汇总表的月份。本批的输入目录整理在
`Reference-tmp/graph_bundle_20260903/data/`，移出的两窗放在同目录的 `_excluded/`。

输入不入版本库，产物入库：转换过程为确定性映射，不引入随机量与补齐值，
同一份输入可随时重建同一份产物。中间件 `jdraw.json` 亦不入库，缺席时 `build.mjs`
照常运行，城市、企业与原文摘录三维退回演示补齐层。

Cloudflare Pages 的构建命令不调用本脚本。产物既已入库，构建环境无须持有原始数据包，
部署链路与既有配置一致。

### 两处拆分

`graph.json` 与 `delta.json` 各拆成两份，拆的是传输一侧，前端在加载层重新并作一份
（`graphData.ts`），下游读到的形状与拆分前一致。

- **技能点一层单列**。它占末窗图谱的八成（节点 20,192 条、边 30,962 条），而封面与
  首页读不到这一层。分开之后两份可并行取回，缓存与重取亦按层各算一份 —— 上三层的
  体量小、随体系变动，技能点一层大、随市场文本增长，两者的更新节奏本就不同。
- **叠层证据单列**。条目的定义、强度与逐窗读数是各图都要读的骨架，逐条证据原文只在
  证据链展开时才读到，而后者占该份的四成有余。

首屏另有一层分块：封面页只读 `manifest.json`（不足两千字节）即可成屏，其余产物与系统
一侧的代码分块在封面绘制之后才发起预取，见 `src/App.tsx` 与 `src/data/manifest.ts`。

## 口径

### 权重的两套

每条边带 `w`（基图权重）与 `e`（合成权重）两个值。基图权重来自招聘信息的统计，
反映市场当期需求；合成权重在基图之上叠加前瞻修正，供市场与前瞻并置比较时使用。
`g` 为该边的 gap 值，即前瞻强度超出市场强度的部分，为零表示市场已跟上。

作市场分析读 `w`，作前瞻分析读 `delta.json`，两者并置的场合才读 `e`。

### 端点校验

四类边的端点须落在对应体系内。基图全窗零越界零自环。合成层的 `task_skill` 有 74 条边
的起点写作技能编码而非任务编码，系算法侧合成阶段挑选高 gap 实体时未按体系过滤，
技能编码与任务编码同以 `T-` 起首所致。此类边在四层结构中无落点，构建阶段剔除，
计数记入 `manifest.dropped`。

### 叠层编号的归一

算法侧的叠层条目按来源流各自计数：论文一侧与新闻一侧都从 `PJ-001` 起编，合入同一份
`new_jobs.json` 后同一编号指向两个实体。2026-04 窗的 `PT-023` 既是"关系丰富文档的
视觉信息抽取"又是"大规模数据迁移执行"。按编号并表会丢掉后出现的那个，末窗四层
合计 2632 条叠层条目中有 173 条因此消失。

构建阶段先做一遍全窗扫描，按"编号 + 名称"建立唯一键：编号首次被某个名称占用时原样
保留，再被另一个名称占用时顺次加 `~2` 后缀。改号条数记入
`manifest.overlayGuards.renumbered`。窗口按时间升序扫描，同一次构建的结果确定，
不同次构建之间亦不变。

### 叠层信号的时间校正

论文一侧的条目 `born_window` 与 `first_seen` 一致，强度逐窗变化；新闻一侧则把同一读数
复制进每一个窗口 —— "平台工程师"的 `born_window` 为 2023-07，却自 2022-07 起每窗都以
0.488 出现。这类条目在其入场窗口之前不构成观测，逐窗序列上表现为一段凭空的平台期，
故按"窗口早于 `born_window`"剔除，剔除次数记入
`manifest.overlayGuards.preBornDropped`。论文一侧无一条命中此判据。

### 叠层记录的存放

算法侧的逐窗叠层是累积的：一条 2022-07 入场的信号在其后每一窗都再出现一次，定义、
来源与证据句逐字重复。四十四个叠层窗下来，同一句证据在产物里存了数十遍。故 `delta.json`
按实体存一份静态记录（`entities` 与 `strengthenDefs`），逐窗只留
`[键, 强度, 来源]` 三元组。证据取末次出现的那份 —— 证据随窗累积，最后一次的集合最全。

来源不提出去：一条信号被招聘市场接住后由 `papers` 变为 `jd+papers`，三源序列按当窗
来源分流，提出去会把入场早的信号一律按末窗来源归类。

### 叠层实体

叠层新实体的编码以 `PJ-` `PT-` `PS-` `PK-` 起首，不在基准体系内但为合法端点，
节点上以 `origin: 'overlay'` 标记。这批条目一并写入节点表，多数还没有任何边，
在图上是只有自己没有连接的孤立节点：新岗位与新能力的发现本身就是叠层要回答的问题，
只收有边的那几个等于把发现结果按连接数筛掉。末窗共 1 个新岗位、38 项新任务、
13 项新技能与 2517 个前瞻技能点。

上一批的四个新岗位多数已在本批转正：`GJ-006` 至 `GJ-014` 九个岗位、`T-36` 至 `T-64`
二十九项任务、`T-DG-02` 至 `T-DG-05` 四项技能，均由叠层写进正式体系，末窗因而只剩
一个尚未转正的新岗位。转正条目在体系文件里带 `graduated` 标记，`delta.json` 另给
本窗转正条数（本批为 6）。

叠层技能点的量是信号强度，落在 [0,1]，与基图技能点的招聘统计权重不同量纲，
不参与市场占比的计算，仅作排序。

### 图上的层级

主图与职业探索页的总览图，第三列一律画到技能这一层（体系 54 项，末窗有边的 52 项），
技能点作为下钻的落点。两层不并排画的原因是数量：技能为封闭体系，一屏读得完；
技能点是随市场文本生长的开放集合，本批逾两万项，铺成一列时行高压到一像素以下，
条长之间读不出差别。

下钻展开时，技能点的量按「经由这项技能的那一份」算，即该技能的需求量乘以该技能点
在这项技能内的边权占比，而非该技能点的总需求。一个技能点可以挂在多项技能下，
总需求为各条路径之和；按总需求排会让通用工具压过专业工具。

展开段另用一把尺子，满格为本技能下最强的那个技能点。技能点的分布极平：一项技能下
头部十来个主流工具之外，其余数千项的边权几乎并列，若与技能条共用一把尺，
展开出来的十二根条会一起压到最小宽度。

### 序列的截断

基图技能点共 17,675 项，逐月序列只覆盖末窗权重前 1200 项。其余条目末窗权重已不足
万分之一，逐月序列没有可读的分辨率。截断阈值记入 `manifest.seriesSkillpointTop`。

### 招聘原文的聚合

汇总表（`jd-summaries/`）是原文表按岗位分层抽样后的子集，本批四十六窗合计 378,068 条；
原文表（`timeline/jd/`）逐窗数万至数十万行、合计 5,789,292 行。两者按 `jobid` 连接，
连中 497,375 行 —— 连接只覆盖抽样入图的那一部分，与 `jdstats` 的口径一致。
同一 `jobid` 在原文表内可重复出现（同一岗位的重复发布），故连中行数多于抽样条目数。

汇总表未含城市与企业两列，原文表则有 `place`、`company` 与 `job_information` 三列。
城市取 `place` 的第一段，共 391 座，逐座入库不截尾；企业按名计，共 81,362 家，
只留每岗前十家 —— 企业没有省一级的汇总，八万余家逐家入库既读不出差别又按岗位数
放大体积。原文每岗保留三条、每条截断至 420 字。

`place` 一列的分隔符有短横线与间隔号两种（"上海-浦东新区"与"上海·浦东新区"），
后者自本批起出现，两种写法在同一窗内混排。只按短横线切时，带间隔号的取值整串留作
城市名，同一座城会按区拆成数十个"城市"：本批 1240 个取值里有 849 个是这么来的，
按省汇总时一并落进"其他"，使该项在属性栏上排到第四位。切分因而按两种分隔符一并处理。

前端把城市按行政区划汇总到 34 个省级行政区（对照表见 `src/data/provinces.ts`）：
391 座城市里尾部大量是个位数的条目，在属性栏上读不出差别；省一级既列得下，
也与"在哪儿招人"这一问的既有认知一致。属性栏上列出全部 34 个省级行政区（含港澳台），
条数为零的照列 —— 零本身是一条读数。省份一组的行数超出画布，故这一组另开一个
定高视窗、组内自行滚动，其余三组不受影响。城市一级仍可在下拉里逐座勾选，
勾掉的城市连同其条数一并退出所属省份的条。

对照表覆盖数据里 391 座城市中的 389 座，未登记的是 `远程办公`（859 条）与 `国外`
（1 条），两者本就不是一个地方，归入"其他"。写作"广东省""红河州""燕郊开发区"
这类带后缀的取值先去后缀再查一次，与直接写市名的落到同一处。

### 职级 × 能力

汇总表逐条带一个职级（`level`）与一组能力要求（`skill_vec_01`），按职级切开即得各档的
能力构成。`jdstats.levels` 为全样本的职级 × 技能计数，不按岗位切也不截尾，
供全站的职级系数取用；`jdstats.byJob[岗位].levelSkills` 为按岗位切开的那一份，
每档只留权重前二十项 —— 一个岗位在一档下平均命中三十余项技能，尾部多为个位数，
进入产物后按岗位数与档数两重放大。

职级列约四分之三有值（`manifest.levelCoverage`，本批 75.0%，上批为 55.7%），
无值的条目不进入本维。
汇总表的五档职级在界面上按年限区间并为三档。

### 熟练度

`prof.json` 给技能一层的档位分布，末窗覆盖入图的 52 项技能中的 46 项，缺
`F-1-01` `F-1-03` `F-1-04` `F-3-04` `F-4-01` `F-4-02` 六项通用素养，与上批缺的是
同六项。算法侧产出的 `name_zh` 字段写的是编码，构建阶段按技能体系补回中文名。

`jdstats.byJob[岗位].skillProf` 给"某岗位对某技能"这一粒度的五档计数，
取自汇总表的 `skill_vec_prof` 列；`jdstats.skillpointProf` 给技能点一层的五档计数，
由同一条招聘信息内其父技能的档位归属推得，只收样本量不少于二十条的那一部分（2326 项）。

界面上一条（岗位，技能点）关系只落一档，而实测给的是一个分布，故按确定性哈希从该
分布中取一档：同一对每次刷新落在同一档，聚合起来的四档比例即实测比例。
这一步是分配而非观测，前端按 `derived` 登记。

### 学历门槛

原文表的 `degree` 一列在上一批四十二万行里整批为空，本批开始有值，占连接条数的
一成上下，其余仍为空；汇总表无此列。正文多数写有明确的门槛语，且算法侧的职级
（`level`）本就是从正文抽出的（`level_source` 记作 `text`），学历沿同一路径可得，
故由 `jdraw.mjs` 的 `degreeOf` 补一道抽取：列里有值时以列为准，为空时抽正文。

列里的取值不循六档轴的写法，另有"中技/中专""高中"两种，故列值同样过一遍 `degreeOf`
归一到轴上。不归一时同一档会在轴上拆成两三个名字各占一格：本批有 433 条落在这两种
写法上，前端的六档轴容不下轴外的档，这些条目会被静默丢掉。

六档由低到高排列，扫到的第一档即门槛：正文写“大专及以上学历，本科优先”时门槛是
大专而不是本科，按低档优先扫恰好取到门槛。“学历不限”排在最前 —— 它是一条独立的
读数，不是最低的一档。判定限于出现学历语境的条目：正文里既无“学历”“学位”“毕业”，
也无任何学历名词时不作判定，此类条目不计入本维的分母。

全批判出门槛 367,517 条，占连接上汇总表的招聘原文条数的 73.9%；分布为本科 69.8%、
大专 22.7%、硕士 6.1%、高中及中专 0.8%、博士 0.4%、学历不限 0.1%。这一维因而是推导
而非观测，前端按 `derived` 登记，界面上写明抽法与覆盖率，不再标演示数据。

### 能力要求的句级归因

汇总表逐条给出该条招聘信息要求的技能（`skill_vec_01`）与各技能下命中的技能点
（`skillpoint_map`，写作“技能:点1,点2;技能:点3”）；原文表给出正文全文。技能点是具体的
技术名与工具名，在正文里以原字面出现，故可反查落点，再由落点定位所在句 —— 该句即这
一项能力要求的支撑句。见 `jdraw.mjs` 的 `attributeOf`。

全批 749,803 个（条，能力项）对中定位到 666,656 个，占 88.9%。未定位到的那一成多，
多是正文只写了能力的概括表述而未点出具体工具。单字技能点（“C”“R”这类语言名）不作为
归因的锚：按字面定位必然误中；它们在技能点一层仍照常计量。

归因逐岗位聚合后保留支撑条数最多的十四项能力，各留三条按企业去重的支撑句，以及按
企业与按城市各前八项的切分。两维切分各带自己的分母（格式为 `[键, 支撑条数, 总条数]`）
—— 下游要算的是提及率，分母若让下游另查，只能查到产出时截过尾的那份企业清单，
两份清单的交集之外就没有分母可用。

招聘侧因而进入了证据链的锚点表：岗位洞察页的“各企业的表述侧重”随之有内容可列。

### 叠层新岗位的任务与技能向量

算法侧未把这一层关联写进四类边：`delta/job_links.json` 四十四个叠层窗合计 299 条、
末窗 1 条，落在 delta 层，不进 `effective` 的 `job_task` 与 `job_skill` 两表。而岗位
空间关系图按 `effective` 的任务构成算距离 —— 零向量与任一岗位的余弦距离恒等于 1，
该值出自零向量的代数性质，不是一次比较的结果，这些点因而一直读不出落位。即便把末窗
那一条计进来，六十项任务里也只有一项非零，距离由单一分量定，同样读不出落位。

`jobvec.mjs` 由已有字段推得一份，按证据形态分两条路径：

- **结构化信号**。叠层条目的 JD 类证据句写作「JD标题：卫星测试工程师｜正文信号：
  技能：数据分析与可视化、……；任务：系统运维、数据分析、生产环境测试；技术栈：TS-01」，
  冒号后的名称即体系内的规范名，逐条解析即得一份计数。这一路径不作任何语义推断，
  只是把算法侧已抽出、但没有写成边的那份信号读出来。
- **文本锚点**。只有论文或新闻证据的条目没有上述信号，改由文本相似度定位：给每项任务、
  每项技能建一份锚点文本，与该岗位的定义及证据句算 TF-IDF 余弦。锚点沿图结构扩写 ——
  任务的锚点并入承担它最多的那几个岗位的技术关键词与它要求最重的那几项技能名，技能的
  锚点并入它下面权重最高的那些技能点名。扩写用的全是图内已有的边，不引入外部词表。

两路径都命中时以结构化信号为主（权重 0.75）：它是从招聘原文里抽出来的读数，文本锚点
是相似度推断，两者不同级。本批末窗只剩一个尚未转正的新岗位（`PJ-010` 虚拟现实工程师），
由结构化信号定位，最高相似度 0.1307，推得任务 24 项、技能 10 项。

相似度的下限一度设在 0.08，低于它即整条不出向量。上一批四个新岗位中有一个（事实核查员）
的相似度为 0.0356，证据只有论文与新闻的英文摘录，与中文任务锚点的词面重合本就稀薄。
判断本身没有变，改的是它落在哪一侧：落在管线一侧，该岗位在图上是一个不给距离、不给
相近岗位的空心点，界面上要为这一个点专设一套空态与几段口径说明；落在界面一侧，各岗位
同口径出图，弱的那一个弱在 `topSim` 上，该字段逐岗位写在 `inferred.jobs` 里，可核可查。
现取后者，下限置零。相似度偏低的岗位，其相近岗位清单只作参考。

产物写在 `graph.json` 的 `inferred` 一节，不并入 `edges`：四类边是实测，这一份是推导，
混在一起会让“四类边均为实测”这句口径失真。前端单独取用（`realGraph.INFERRED_EDGES`），
逐条标 `provenance: 'derived'`，目前取用它的有两处：岗位空间关系图的距离，与岗位定义
五要素里的核心职责。

### 岗位一级归属的补录

算法侧按批次积累若干轮后才统一归类，本批 `GJ-006` 至 `GJ-014` 九个新转正岗位的
`category` 为空字符串。空归属会在按类别切分的各图上多出一档"无一级归属"，且这九个
岗位在图上一律落到同一处。

补录表在 `job-category-overrides.json`，逐条按岗位定义判入既有九类之一，附判入的理由；
构建脚本与前端的体系视图（`realTaxonomy.ts`）共用同一份，故两处给出的归属必然一致。
体系文件里有值时以体系文件为准 —— 算法侧补齐归类后，把对应条目从本表移除即可。

本批末窗入图的九个转正岗位中有两个（`GJ-008` `GJ-012`）走这条补录。

### 岗位定义的三项要素

岗位体系只给名称与定义，五要素中的核心职责由该岗位承担的任务给出，其余三项本节由
汇总表已有的两列推出，写入 `jobdef.json`：

- **必备技能**取覆盖率高的那一批。覆盖率 = 该岗位的招聘信息中提到某项技能的条数占比
  （`skill_vec_01`）。三成以上的招聘信息都提到，即为这个岗位的通例，按覆盖率降序至多
  八项；无一项过门槛时退到一成五的门槛取前五项。
- **加分技能**取另一头：提的企业不多，可一旦提到，要求的熟练度反高于必备技能的平均
  水平。熟练度 = 同一批条目中写明程度词的那一部分的平均档位，P1 至 P4 记 1 至 4
  （`skill_vec_prof`）；未写明程度（U）的不计入均值 —— 把它摊进档位里，等于把"没写"
  说成"要求不高"。另设样本量下限（二十条与该岗位条数百分之零点五中的大者），否则
  几十条里出现两三次的偶发项会因均值不稳而排到前面。
- **典型应用场景**取汇总表的技术栈一列：该列逐条标注这条招聘信息属于哪些技术方向，
  按岗位聚合后即"这个岗位实际投放在哪些方向上"。一条招聘信息可同时标注多个方向，
  故各项占比之和大于一，界面上写明这一点。

104 个有招聘投放的岗位平均得必备 7.5 项、加分 2.5 项、场景 3.9 项；十五个岗位没有
加分项（超出必备均值的技能均未达样本量下限），界面上如实写出，不以低样本量的项充数。

叠层新岗位没有招聘投放，上面这套无从谈起，三项改由已有的两处推得，逐条记
`via: 'inferred'`：必备与加分取 `inferred.jobSkill` 与"该岗位承担的任务反过来要求的
能力"（沿 T-S 边取）的加权合成，权重居前的一批为必备、其后一段为加分；典型应用场景
取能力构成最相近的五个既有岗位所投放的技术方向，按相似度加权。两路的配比为 3:7 ——
叠层证据里直接点到的技能以通用素养居多（论文与新闻谈一个新岗位时谈的多是"要能持续
学习、要能沟通"），只据此列必备技能，整张卡片会全是软技能。

### 下一季度的能力构成预测

算法侧另有一路时序预测（Chronos-2 零样本），以各（岗位, 技能）的季度份额序列为目标，
做两遍 2026-Q3 的预测：

| 字段 | 含义 |
|---|---|
| `p50_uni` | 只用份额序列自身的单变量预测 |
| `p50_cov` | 另把该技能当季在论文与新闻里的情报占比作为仅过去协变量加入后的预测 |
| `signal` | 两者之差。为正即"把论文与新闻算进来之后，这一项的下季占比被上调" |

后者正是本系统所称的前瞻信号在预测一侧的落点。逐条按岗位归拢后写成 `forecast.json`；
本批 104 个岗位、4,618 条（岗位, 技能）对，名称与体系逐条对得上，无跳过。

输入是一份独立的 CSV，随算法侧另行交付，不在图谱数据包内，置于
`data-pipeline/forecast/forecast_2026_Q3_skill_share_cov.csv`；缺席时本节不产出，
界面上相应一块不画。

既有岗位能力动态页据此在能力年轮外圈画一环预测环（虚线，`predicted` 置真），
并列出下一季度前瞻信号两头各前六项。预测环不产出变更条目 —— 界面上的"本季变动"
一律取最外一个**实测**环所在的那一季。

### 领先月数与信号时效

两项都由已有的三源序列现算，落在前端的加工层（`realGraph.ts` 的 `buildRealSignals`），
不进本目录的产物：它们是两条实测序列的导出量，与序列同源，另存一份只会多一处可能
对不上的地方。

- **领先月数**：前瞻曲线相对招聘曲线的最优滞后。把前瞻曲线整体右移 k 个自然月后与
  招聘曲线求相关系数，取相关最高的那个 k。两条序列先取相邻观测之差再求相关 ——
  看水平值时，一条自首窗起就居高不下的技能与任何一条同样走高的曲线都高度相关，
  滞后取到哪个 k 全由长期趋势定；看变化量时问的才是"论文这一头抬起来之后，招聘那一头
  隔多久跟着抬"。观测窗口不连续，故先把两条序列摊到自然月轴上，缺测的月份成对剔除。
  相关系数下限 0.35，滞后上限为观测跨度的一半。本批 121 条已被招聘市场确认的信号中
  判出 45 条，最短一个月、中位十个月、最长二十四个月。
- **信号时效**：末窗的前瞻强度相对该条目自身历史峰值的比例。算法侧的叠层强度按月
  衰减，一条提出后再无人跟进的信号会逐窗走低，该比例即读作"这条信号现在还有多新"。
  此前此处恒置 1，整列因而一律显示 100%，读不出差别。

### 本批数据未包含的维度

企业类别分布：迁移包按 `include_jd_dataset=false` 打包，未含原始招聘数据集，派生出的
原文表只选了十四列（`jobid,job,funtype,salary,place,work_year,degree,company,opentime,
job_information,_table,techstack,level,level_source`），其中没有企业类别；汇总表的
二十四列中同样没有。仅凭企业名判定不可靠：人力资源服务企业多为代招方，不是用人单位。

**该维本轮整条撤除**，不再由补齐层给出形状。此前它与另三组并排在职业探索页的属性栏
里、共用同一种条长读法，读者无从分辨哪一组的高低是测出来的。属性栏现为省份、学历、
经验三组，均有实测来源；簇内岗位分布图的横轴改用招聘信息逐条标注的技术方向
（`techStacks`，同样取自汇总表的技术栈一列）。该维仍记入 `manifest.absent` 作为数据
一侧的记录，但界面上已无落点。

证据链只保留可核对的锚点句，完整原文在算法仓库。

另有两处缺口不在 `absent` 清单内，但同样是本批数据的缺项，记在此处备查：

- `GJ-006` 至 `GJ-014` 九个本批转正的岗位，`category` 一律为空字符串，`GJ-001` 至
  `GJ-005` 则有值。前端归入"无一级归属"，全景图谱页的岗位类别一栏因而多出这一档
  （末窗有 2 个入图岗位落在其中，加 1 个叠层新岗位共 3 个）。类别是既定归属而非
  推断量，此处不代填。
- 体系内 145 个岗位末窗入图 104 个，按类别看：软件开发 36/36、人工智能与数据 20/21、
  产品与设计 16/16、运维与IT支持 12/12、技术管理 6/6、测试与质量 5/5、安全 4/4、
  网络与通信 3/11、硬件与半导体 0/25。硬件与半导体一整类末窗一条边也没有，
  界面上不可见；该类岗位的招聘条目未落入算法侧的 IT 口径（`it_scope_v1`）。

界面上仍标为补齐的只剩两项：证据原文全文（只保留锚点句），与人岗匹配页的示例简历及
技术名对照词表。两项列在 `src/data/provenance.ts` 的 `ABSENT_DIMENSIONS`，顶栏的数据
窗口标读它；各页图上不再挂演示数据标，需推导一层的维度（学历门槛、要求程度档位、
叠层新岗位的任务构成与定义三要素）改在该图自己的问号里写明推法与覆盖率。

叠层的既有条目增强按体系编码记录，落在岗位、任务、技能三层；技能点一层叠层产出的是
新实体而非对既有条目的增强。故前瞻分析的三张图不设技能点档：该层没有
"论文先于招聘出现"这一对时刻可比。

### 论文标题

证据表逐条只给来源文档的 arXiv 编号，不设标题字段。抽取阶段留下的证据句里有一类以
"标题："起头，其内容即该文的标题，逐窗扫一遍即可按编号建起标题表。本批引用到 2297 篇，
其中 2225 篇由此得到标题，其余 72 篇录于 `paper-titles.json`：33 篇取自 arXiv 官方接口，
40 篇取自迁移包内 `data/papers/**/<编号>.txt` 的【标题】字段，与算法侧同源。补充表是
静态文件，构建过程因而不联网，仍为确定性转换。本批引用到的论文全部有标题可显示。

### 权重尾部

技能到技能点一层约 61% 的边权重在四位小数下取整为零（上批为 45%），系跨窗衰减系数
α=0.85 累积所致，不表示该边不存在。窗口数由十九增至四十六，累积的窗数随之翻倍，
取零的比例因而上升。渲染时按阈值截断，不作存在性判定。

## 更新流程

1. 算法侧产出新窗口后，将数据包解压到 `--src` 指向的目录，按上文"运行"一节整理布局：
   汇总表移到 `jd-summaries/`，结转窗移出 `graph/`；
2. 校验数据包的 SHA-256，与随包的 `.sha256` 文件比对；
3. 把末窗 `base/` 下的 `jobs.json`、`tasks.json`、`skills.json` 复制到
   `src/data/real/`（分别对应 `jobs_v2.json`、`tasks_v3.json`、`skills0821.json`）。
   三份体系文件与图谱产物须同源，否则同一条目在图谱里查得到、在种子里查不到；
4. 核对原文表的列与取值写法有无变化，尤其是 `place` 的分隔符与 `degree` 是否有值 ——
   这两处在本批都变过，静默走下去会得到看似正常的错数；
5. 运行 `jdraw.mjs`，核对终端打印的逐窗连接条数、城市数与学历分布；
6. 运行 `build.mjs`，核对各层规模、`manifest.dropped` 与 `manifest.overlayGuards`；
7. 核对新增的体系条目有无归属缺失（岗位的 `category`、技能的能力组），
   能力组若有新增，`CapabilityAnnuli` 的 `GROUP_HUES` 须同步补色；
8. 逐页核对界面：断档、职级覆盖率与档位构成三处的口径说明由产物现算，无须手改；
9. 核对本轮新增的两份输入是否仍然适用：`job-category-overrides.json` 里已被算法侧
   补齐归类的条目应予移除；`forecast/` 下的预测 CSV 随算法侧的新一轮预测更换，
   其 `forecast_quarter` 应晚于末窗；
10. 提交 `public/data/` 下的产物与 `src/data/real/` 下的三份体系文件；
11. Cloudflare Pages 按既有配置自动构建发布。
