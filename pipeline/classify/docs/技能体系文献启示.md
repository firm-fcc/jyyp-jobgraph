## 2. 结构性优化（影响体系架构）

### 2.1 Skill/SkillPoint 分层获得强验证 —— ESCO 4.0

**ESCO 4.0 的教训**：ESCO 分类体系中"收录了 Android、iOS 等具体商品名，却缺失了更泛化的技术大类"，导致分类体系既臃肿又不完整。

**对我们的意义**：这正面验证了 v2 四层设计 `Skill（稳定类别）→ SkillPoint（具体工具）` 的必要性——**Skill 层不收商品名**，Android/iOS/TensorFlow/LangChain 全部归 SkillPoint 层。建议把这条固化为构建原则写入 v0.2：

> **Skill 层收录规则**：只收能力类别（"移动应用开发""深度学习"），不收任何品牌/框架/平台名（Android、iOS、PyTorch、Kubernetes 一律进 SkillPoint）。

### 2.2 skills.json 增加 skill_type（hard/soft）字段 —— SkillSpan / SkillNER

SkillSpan、SkillNER 均以"硬技能/软技能"二分组织抽取；v1 设计的噪声过滤也要求对软技能降权。因此 **skills.json 每个条目建议增加 `skill_type ∈ {hard, soft, hybrid}`**：

- `hard`：技术技能（T 类绝大多数）
- `soft`：基础通用技能（F 类）
- `hybrid`：兼具技术与软性成分（如 T-AI-11 负责任AI、F-5 AI素养）

作用：①Extractor 输出可直接标注类型；②图谱统计时对 soft 降权（规避样板话术）；③人岗匹配时可区分硬/软差距。

### 2.3 F 层对齐 21 世纪技能框架 —— van Laar

van Laar 系统综述（1592 篇筛出 75 篇）给出 7 核心 + 5 情境技能。与我们 F 层对照：

| van Laar 核心技能 | 我们 F 层 | 状态 |
|------------------|----------|------|
| Technical | T-* 全部 | ✓ |
| Information management | T-DA-02/04（偏技术侧） | △ 建议 F 层补"信息管理素养" |
| Communication | F-2-01/02 | ✓ |
| Collaboration | F-2-03 | ✓ |
| **Creativity（创造力）** | 无 | ✗ **建议新增** |
| Critical thinking | F-1-02 | ✓ |
| Problem solving | T-DA-01（并入原 F-1-03） | ✓ |

| van Laar 情境技能 | 我们 F 层 | 状态 |
|------------------|----------|------|
| Ethical awareness | F-4-02 + T-AI-11 | ✓ |
| Cultural awareness | 无 | ○ 可选（技术岗非必需） |
| Flexibility | F-3-04 | ✓ |
| Self-direction | F-1-01 | ✓ |
| Lifelong learning | F-1-01 | ✓ |

**具体建议**：
- 新增 `F-1-04 创造力与创新思维`（cs23 亦有 "Inventive" 对应）
- 新增 `F-2-06 信息管理与数字素养`（van Laar "information management"，区别于 T-DA 的技术性数据管理）

### 2.4 知识(Knowledge)与技能(Skill)的区分 —— ESCO 4.0

ESCO 4.0 发现"ESCO 正确管理了技能，但缺少 I4.0 所需的知识(knowledge)"。这提示分类体系内部应区分"知道什么"与"会做什么"。

**建议（轻量方案）**：不单独设 Knowledge 层（避免过度设计），而是沿用 Onet 现有做法——每个 Skill 条目定义同时含**知识基础**（"掌握…原理"）+ **操作能力**（"具备…能力"）两段。在 skills.json 中可拆为 `knowledge_base` 与 `ability` 两个字段。

### 2.5 Industry 4.0/5.0 技能覆盖缺口 —— ESCO 4.0 / IT 5.0

ESCO 4.0 明确指出其缺失的 4.0 技术：数字孪生（digital twins）、信息物理系统（CPS）、制造执行系统（MES）、协作机器人、智能体模型、无线网络、RFID、蓝牙。IT 5.0 论文同样给出最新 IT 岗位技能清单。

**与我们体系的对照**：

| ESCO 4.0 缺口 | 我们体系 | 建议 |
|--------------|----------|------|
| 数字孪生 / CPS | 无 | **建议新增** `T-SYS-08 数字孪生与信息物理系统` |
| 智能制造 / MES | 无 | 建议新增 `T-SYS-09 智能制造与工业互联网` |
| 协作机器人 / 智能体 | 智能体已有（T-AI-08） | 协作机器人可作 SkillPoint |
| 无线网络 / RFID | T-SYS-04 网络通信 | SkillPoint 级，不需新增 Skill |

> 说明：赛题重点为 AI/大数据/操作系统/算法，智能制造为相关延伸，**建议先以 2 个新 Skill 占位，待 JD 数据验证后再定保留与否**。

## 4. skills.json 输出规范建议（文献驱动的字段设计）

综合 e-Skills Match（标准映射）、ESCO（层级编码）、抽取论文（Extractor 对接）、预测论文（演化支持），建议每个条目：

```json
{
  "code": "T-AI-05",
  "name_zh": "提示设计与提示工程",
  "name_en": "Prompt Design & Engineering",
  "knowledge_base": "掌握零样本/少样本提示、上下文操控、提示注入风险…",
  "ability": "能撰写结构化提示、设计 RAG 结合提示、排查提示故障…",
  "skill_type": "hard",
  "domain": "T-AI",
  "group": "人工智能与智能技术",
  "status": "emerging",
  "esco_mapping": "S4.2.10（如可映射）",
  "exemplars": ["LangChain", "OpenAI API", "RAG 框架"],
  "source": ["IMDA TSC2/3", "O*NET AI补充", "文献-ESCO4.0"]
}
```

- `status ∈ {emerging, growing, stable, declining}`：**支撑叠层 ΔG 演化联动**——taxonomy 层面的静态标签 + 图谱层面的动态置信度（v2 设计已有）
- `esco_mapping`：后续可对接 ESCO 全量分类做术语对齐
- `exemplars`：SkillPoint 示例，即 SkillPoint 层的种子，由 JD 数据扩充
