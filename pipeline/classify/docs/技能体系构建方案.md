## 2. 粒度分析与三源互补

### 2.1 在 v2 四层体系中的定位

v2 设计定义 `Job → Task → Skill → SkillPoint`，其中 **Skill = 稳定能力类别**（跨越数年）、**SkillPoint = 具体工具/技术**（快速迭代）。本次构建产出 **Skill 层**，SkillPoint 层暂由 JD 数据驱动。

### 2.2 三源互补关系

```
Onet.json（骨架）──────────────────┐
  技术 13 + 基础 15，粒度正适合 Skill 层 │
                                     ▼
cs23.json（校验）──→ 技术覆盖完整性对照 ←── IMDA + O*NET AI补充（升级）
  17 个学科知识域     查漏：并行分布式、     9 个 GenAI TSC + 17 项 AI 技能
  确认无遗漏          HCI、数据管理           补上 Onet 缺失的生成式AI专项
```

### 2.3 关键判断：AI 技能按什么粒度入 Skill 层

赛题核心是大模型/AI 岗位，若沿用 Onet 粗粒度（AI 只有 1 个 T8），则"新岗位识别""技能动态更新"无从谈起。因此**将 IMDA 的 9 个 TSC 与 O*NET 补充的 AI 技能提升为 Skill 层新类别**：

- **依据**：这些能力类别在 2025-2026 已具稳定性；易变的工具名（LangChain、CrewAI、vLLM…）才属于 SkillPoint。
- **风险**：粒度越细，对 Skill 层稳定性要求越高，需靠 SkillPoint 层承接工具级变化。
- **范围界定**：本次技能体系**聚焦信息技术领域的人工智能技术**，暂不纳入智能制造/工业互联网专项（留待数据验证）。

## 3. 构建原则

1. **Skill 稳定、SkillPoint 迭代**：本方案只定义 Skill 层；具体工具/技术名词归 SkillPoint。
2. **Skill 层不收商品名**（ESCO 4.0 教训）：品牌/框架/平台名一律进 SkillPoint，Skill 层只保留能力类别语义。
3. **每条技能必须标注可查询来源**：来源须定位到具体文件 + 编码/条目号（§5.1 记法）。
4. **每条技能标注 skill_type**：`hard`（技术）/ `soft`（通用）/ `hybrid`（兼具）。
5. **Onet 骨架 + AI 升级 + cs23 校验**：以 Onet 28 项为底座，IMDA/O*NET-AI 升级 AI 专项，cs23 查漏补缺。
6. **面向赛题**：覆盖 AI、大数据、操作系统、算法等数字经济领域。
7. **兼容 v2 四层体系**：本 Skill 层作为 `J-S`、`T-S` 边目标节点，承载 `S-SP` 多对多挂载。
8. **基础通用技能纳入但降权**：软技能用于简历匹配完整性，图谱统计时降权。
9. **去冗余**：能力语义重复的条目合并，保留一项并在定义中注明边界（§6）。
