# 基图构建成本估算（2026-08-25 修订）

基于 2025-10 全量实跑的实测数据，给出单窗口成本基线、规模外推与改进路径。
2026-08-25 严格岗位筛选（it_scope + 严格门 + 无信号降级）落地后 2025-10 重跑，
IT 池 2904 → 1228（-58%），各阶段调用/费率同步下降。

## 2. 规模外推

句级缓存（`cache_merged_v2`）、`jd_prof_evidence_cache`、`jd_job_cache` 跨月可复用，但实测跨月句级去重偏低（月内 33%、跨月更低），相邻月有限受益。**严格门下 A 的 LLM 归类成本（103 次/月）远小于其剔除的 B/C 处理量（IT 池 -58%），是净省钱项。**

| 范围 | JD 量级（估） | 调用（估） | 花费（估） | 备注 |
|---|---|---|---|---|
| 单月（2025-10 重跑） | ~1,228 IT | ~2,500-3,000 | **~15-18 元** | 严格门基线（A 103 + B 1406 + C 减半） |
| Q4（10/11/12） | ~4-5K IT（11/12 月更大） | ~9K-12K | ~55-70 元 | 11/12 月 JD 量约为 10 月 2-4 倍；缓存部分复用 |
| 全历史 53 窗口 | ~数十万 IT | ~数十万 | ~800-1,400 元 | 月量差异大（2021-2024 较小）；缓存累积但跨月复用有限 |

> 外推为粗估：实际受月度 JD 量、句级/证据级去重命中率、限流重试率共同影响。Q4/全量跑前建议先零 LLM 预演（`classify_job --strict --stats` 测 IT 池 + `run_jd_extract` 小样本测句级 miss）再线性外推。

## 3. 成本结构与瓶颈

- **B（抽取）是调用与 token 双大头**：3255 调用 / 6.26M tokens，占合计 ~55% 调用、绝大部分 token。merged 已把句级调用减半（vs 旧 2-pass），进一步降本须降"句级去重命中率低"——但研究证明 JD 需求句模板化仅 ~33%，难有干净的大幅压缩（merged 整体/段对齐均牺牲完整性，已否）。
- **C（熟练度）2,685 调用**：证据级去重仅 6%（证据是句束、复用低），故调用偏高。52 块契约失败源于 LLM 偶发多输出 `evidence` 字段（严格契约拒绝），可低成本修复。
- **C 的 ~2× 调用（待查优化点）**：2685 调用 vs 理论 chunk 数 ~1307（15681 唯一对 / 12）≈ 2.06×。疑似 **partial-retry**——LLM 在一个 chunk（12 对）内未返回全部技能的结果 → `codes <= set(out)` 不成立 → 整块重试一次。后续可：prompt 强化"对每个输入技能都给结果（不足给 U）"+ 验证，或缩 chunk，预期 C 调用减半。注：`n_retries` 统计似有欠计（35 vs 实际重试），仅作参考，以 `n_calls` 为准。
- **限流重试**：B 理论批 2115、实际 3255（重试率 54%），是 DeepSeek 持续高频调用下的 429/超时重试。并行化 + 合理退避节奏可压。

## 4. 改进路径

### 4.1 LLM 调用全阶段并行化（提速，不降调用数）✅ 2026-08-24 / 2026-08-26
- LLMClient 批次并发（`ThreadPoolExecutor`，`settings.yaml → llm.concurrency` 控制，默认 20，1=串行）；
  `_gather` 并发跑各批次、主线程顺序合并结果；token/调用计数加锁；缓存写入顺序做（避免并发写文件交错）；
  批级容错（单批失败不中断整窗，未答单元不缓存、下次自动重试）。
- 2026-08-26 补齐三处串行瓶颈：A 门 LLM 批间并发（实测 12 批 4.7s）；B 改两遍式（全窗唯一句
  批并发分类 + 逐 JD 组装全缓存命中，实测 251 句 16 调用 31s）；C 改两遍式（串行 prepare 保
  跨 JD 证据去重的"同证据同判定"语义，全窗 chunk 并行，实测 20 chunk 15s）。
- 附带：窗口归类缓存 `{窗口}.jobcls.json`（大窗扫描 33min×3 → ×1）；classify_job 异常分支
  死代码修复（错误记录原本不可达）。
- 大窗（cap=1万）墙钟预估（实测波延迟外推，并发 20）：A ~30min + 扫描 ~33min + B ~2h + C ~2h ≈ 4-5h/窗（旧路径 >20h；调高 llm.concurrency 可线性再压）。

### 4.2 C 契约失败修复（降失败/重试）✅ 2026-08-24
- `_evaluate_chunk` 校验前剥离 LLM 偶发回显的 `evidence` 字段（输入句，非契约字段），保留对其他未知字段的严格拒绝。

### 4.3 退避节奏优化（降 B 重试）✅ 2026-08-24
- `_post` 重试退避由固定值改为指数退避 + 抖动（`(2^attempt)*2 + random(0,2)`），高并发下减少 429 聚集。

### 4.4 严格岗位筛选（IT 池 -58%，各阶段调用全面下降）✅ 2026-08-25
- **A 严格门**（`jd_gate.strict`）：仅岗位名直收，关键词命中送 LLM 复核（+103 调用/月）；
  **it_scope 岗位范围**（34 岗排除集）+ **B 无技术信号降级**。首跑零技能 JD 113/2820 双零中，
  重跑后仅 2/1196。A 增量成本远小于 B/C 节省（B 3255→1406 调用、token 6.26M→3.07M）。
- **skillpoint prompt v2 + 后置清洗**：唯一值 6641→1018，品牌/设备/泛指残留清零（缓存 v2 隔离重抽）。

### 4.5 C 调用减半三件套 ✅ 2026-08-25
- **软技能门控**（`jd_proficiency.soft_gate`，默认开）：F- 技能无梯度词 → 确定性 U 免 LLM（首跑 F 类对占 57%）；
- **输出完整性质约**：prompt 明确"results 逐一覆盖每个输入技能、条数相等"，压 partial-retry；
- **缺失补发重试**：部分成功时只重发缺失技能对（原整块重发浪费一半 token）。
- 下游约定：U 在人岗匹配按最低档要求对待（技能存在即要求，未写梯度按 P1）。

### 4.6 降采样路径（Stage S，2026-08-26 已实现）✅
- `graph/jd_sample.py`：窗口 IT 超 cap（默认 1 万）时分层封顶抽样——岗位层比例分配 +
  稀疏岗保底（floor=30）+ 确定性哈希 + 逆概率加权（`sample_weight` 乘入 D 聚合与 skill_prof）。
  A 门保持全量（精确分母 + 分层标签，~5% 成本）。2025-10 全量基线蒙特卡洛验证：
  rate=10% 三类主边 Jaccard ≥0.96、漏边权重 ≤0.3%、岗位层零丢失（详见 graph/README）。
- **Stage S0 大窗预抽样（2026-09-03，`graph/jd_pre_sample.py`）**：A 门 LLM 兜底是唯一随窗
  规模增长的成本项（B/C 已被 S cap 封顶）——窗口 unique 指纹 > 60k（settings
  `jd_sampling.presample_cap`，≤0 关闭）时确定性哈希预选 60k 个，A 门只归类已选键
  （下游全链经 jobcls 自动受限），w0=N/k 复合进 S 权重保持无偏。**量级勘误（重要）**：
  新批次 CSV 描述字段内嵌换行，wc -l 虚高 ~14×——真实记录 2026-01 29k（unique 25.9k）/
  02 41k（37k）/ 03 101k（91.9k），60k 阈值恰只让 2026-03 触发（65.3%，w0=1.531，
  干跑实证 A 门 LLM 判定 6.4 万→4.2 万条省 35%）；历史最大 2022-07（27.3 万 unique）
  曾全量跑通，未触发窗零行为变化。预抽样窗 IT 总量为估计值（×w0 复原），转正 jd_docs
  仍按基面硬计数。
- 全量成本对比如下；执行入口 `run_pipeline.py --window {月}`（逐窗时序 S0→A→S→B→C→D）：

| 方案 | 保留 IT | 峰价（B/C+A） | 谷价 |
|---|---:|---:|---:|
| 全量 | 118.9 万 | ~18,000 | ~10,400 |
| cap=1 万 | 36.9 万 | ~6,650 | ~3,835 |
| cap=2 万 | 59.0 万 | ~9,740 | ~5,620 |

### 4.7 待办优化点
- B 限流重试率仍 ~50%（理论批 940 → 实际 1406）：DeepSeek 高频 429 所致，可再调并发/退避节奏。
- 论文/新闻 ΔG 批循环仍串行（一次性静态语料 ~2-4h 墙钟，可接受；如需提速按同模式并发即可）。

## 5. 单月成本估算公式（供预算）

```
单窗口花费 ≈ A(送LLM条数/20) + B(唯一句/批15 × (1+重试率)) + C(唯一对/12 × (1+C重试率) - 软技能门控免调部分)
           ≈ n_IT_JD × 0.012 元/JD（首跑基线） → 严格门后 ~0.005-0.006 元/JD
```

## 6. 复用与断点续跑

- `cache_merged.jsonl` / `jd_prof_evidence_cache.jsonl` / `jd_job_cache.jsonl` 持久化、按文本指纹/证据指纹去重：同 JD/同证据只判一次，重跑/跨月同文免费。
- 断点续跑：B/C 均支持（缓存命中即跳过 LLM）。中断后重跑只补未缓存部分。
- 重算口径变更（rubric_version / 体系基准 sha256 变）会使对应缓存失效重算（meta 记录便于追溯）。
