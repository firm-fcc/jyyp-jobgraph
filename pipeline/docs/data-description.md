## 2. 招聘广告（IT 相关 JD，已采集）

- **系统角色**：基图 G_base 的**唯一**构建来源，产出 J-T（岗位→任务）、J-S（岗位→能力）直接边；四类数据中最关键。
- **来源**（两批）：
  - **2025-2026 批**：远端 MySQL `job51` 库 27 张 `job_*` 表（配置 `codes/jd_fetch/config.yaml`）；
  - **JD-Origin 批（2026-08-15 并入）**：早期全量数据 `data/JD-Origin/`（`tencent_cloud_job51.sql.zst` 全库 dump 2022-08~2023-06 + `51job/` 28 个单表 dump 2023-07~2024-09），已导入本地 MySQL `51job` 库（74 张 job 表共 48,617,226 行，逐表与 dump 行数精确校验一致；company/crawl_info 表族未导入），配置 `codes/jd_fetch/config_origin.yaml`。
- **筛选方式**：扫描每条 JD 的 `funtype` 字段，对照岗位体系（§6.2）判定是否信息技术相关；`funtype` 支持 `"A or B"` 多值，任一部分为 IT 即保留。两批各用一份 funtype→IT 映射：2025-26 批 `funtype_it_map.json`（原机器生成）；JD-Origin 批 `funtype_it_map_origin.json`（本地重建：现有 CSV IT 串种子 + 体系名/映射记录种子 + 规则合并 + LLM 兜底 + 负证据对齐，211/1161 parts 为 IT）。
- **数据集（`data/jd_dataset/`）**：

| 指标 | 2025-2026 批 | JD-Origin 批（2022-2024） | 合计 |
|------|--------------|---------------------------|------|
| 全量 JD（表） | 6,481,954（27 表） | 48,617,226（74 表） | 55,099,180 |
| IT 相关行（按 funtype 过滤） | 503,057 | 5,406,477 | **5,909,534** |
| distinct jobid | 389,802 | 2,013,711（跨快照重复率 62.8%） | — |
| opentime 覆盖 | 2025-01 ~ 2026-05 | 2021-06 ~ 2024-09（33 个月） | 2021-06 ~ 2026-05 |
| 导出 CSV | 22 个 | 40 个 | 62 个（约 6.3GB） |

- JD-Origin 批与 2025-26 批 jobid 重叠仅 57,733（2.9%），两批衔接互补；完整验证报告见 `codes/jd_fetch/output/import_report.md`。
- **字段**：`jobid, job, funtype, salary, place, work_year, degree, company, opentime, job_information, _table`（JD-Origin 批表无 work_year/degree 列，动态剔除；`summary.json` meta 含 `origin_extension` 追加记录）。**双维度标注列（2026-08-20 v2.1，全量运行待执行）**：`techstack`（多标签技术栈 code，`TS-01|TS-09` 形式，体系见 §6.4；逐 JD 内容归类 = 词库快路 + LLM 兜底）、`level`（L0 实习/应届 ~ L4 专家五档）、`level_source`（work_year/text/title 判级依据）——引擎与验证见 `codes/jd_annotate/`（`docs/code-description.md` §3.9）
- **加工要求**（规划）：薪资加权 `weight(jd)=log(1+salary/salary_median)`、历史衰减（α=0.85）、抄袭去重（相似度>95% 仅留最早一条 + 结构指纹）。
- **赛题量化目标**：100+ 岗位 JD 测试集，JD 解析 / 要素提取 / 人岗匹配准确率均 >90%。

- **行数口径注意（2026-09-03 实测）**：timeline 月度 CSV 的 `job_information` 字段内嵌换行（多行职责列表），`wc -l` 统计物理行会**虚高约 14 倍**——量级与成本估算必须以 Python csv 解析后的记录数为准（2026-01 物理行 424,894 / 真实记录 29,356；2026-03 物理行 1,477,727 / 真实记录 101,109、唯一文本指纹 91,860）。历史批次（2022-2024）多为单行记录，wc -l 近似成立。

### 2.1 JD 重复文本分析（2026-08-07）

对全量 IT JD 按正文文本统计重复情况（为评估"去重 / 反抄袭"策略提供依据）：

| 指标 | 数量 |
|------|------|
| 总行数 | 503,057 |
| 原始文本唯一 | 358,917 |
| **归一化（合并空白）+ 截断后唯一** | **342,471** |
| 重复组数 | 75,339 |
| 重复组占的行数（额外） | 143,847（占全量 28.6%） |

- **重复度分布**：以"重复 2 次"居多（56,078 组），但有极值——单条 JD 文本重复 **1007 次**（电力运维工程师，2 家公司共用模板，跨 2024-11 ~ 2025-06 反复发布）。
- **成因**：① 同一公司 / 关联公司反复刷新岗位重复发布；② 招聘方直接复用他人模板（JD 同质化 / 抄袭）。对应赛题"反抄袭 / 时效性"关注点。
- **影响**：① 全量送 LLM 成本浪费；② 重复文本会被误计为多个独立岗位信号，扭曲频次统计。
- **当前处理**：① 精确去重——各加载层按 `jd_text_key`（归一化文本指纹）去重，保留每种内容首条；② **近重复（抄袭）过滤（2026-08-28 起，Stage D0 `graph/jd_dedup.py`）**——正文 3-gram simhash64 分块候选 + 海明 ≤6 + Jaccard ≥0.95 双确认，簇内保留最早发布，变体在 S/B/D/jd_delta_v2 在线过滤（对应 §2 加工要求的"相似度>95%"）。实测：2022-05 窗 10,526 条唯一 IT JD 中抄袭簇 541 个、变体 784 条（7.4%）；2022-06 窗 42,315 条中簇 2,164 个、变体 2,907 条（6.9%），最大簇 24 条。跨窗时序抄袭留作二期。


### 3.4 信号密度评估（sources_summary.csv）

## 4. 科研论文（arXiv 文献图书馆）

### 4.1 系统角色与来源

叠层 ΔG 的**主信号**（学术萌芽，领先 JD 约 1-3 年），供 Evolution Analyzer 计算实体强度 `E_arxiv` 与 JD 侧差距 `gap(E)`。数据来自 arXiv 全库按赛题筛选分级。

- 全量筛选入库：**160,720 篇**（S/A/B/C 四档，`01_全库总索引.xlsx`）
- 全文就绪：**207,546 篇** txt（`data/fulltext/*.txt`）
- **本地数据（2026-08-20 恢复）**：全库六专题 × S/A 两档（B 档按总量控制策略未入库）。源包 `文献图书馆_XH-202621.zip`（约 4GB）选择性解压至 `data/papers/`（S+A 共 23,230 个 TXT / 2.6GB）；**跨专题同文去重后 8,097 篇唯一论文**（S 197 / A 7,900——S 档与全库总索引精确一致），去重由 `paper_parser.scan_papers` 按 (文件名, md5) 自动完成
- **2022 全库批次（2026-08-27 并入）**：`arxiv_txt_2022.zip`（arXiv 2022 全量 185,973 篇按关键词 v2 分档：S 51 / A 2,222 / B 7,295 / C 13,358）。源 TXT 为 arXiv **元数据裸格式**（Title/Authors/Published/Abstract，无全文），经 `paper_signal/arxiv_ingest.py` 以批次索引 xlsx 为权威字段源转换为标准头块格式后入 `data/papers/arxiv2022/`（仅 S/A 共 2,273 篇，命中维度沿用六专题命名）；与既有语料 arXiv ID **零重叠**

## 5. 与算法模块的对接点

| 数据/体系 | 消费方 | 对接方式 |
|------|--------|----------|
| 招聘广告 | Graph Builder | IT JD → 节点与边证据 → 基图（P0 最优先） |

### 6.2 岗位体系（Job 层）

- **产出文件（v2.0，当前标准）**：`classify/Jobs/jobs_v2.json` —— **9 个一级类别 + 131 个岗位**，每岗含 LLM 生成的 `definition / keywords / boundary / name_en`；`funtypes` 保留（溯源 + JD 抽样），`source_codes/source_names` 记录 v1 合并来源。
- **构建方式（v2.0，2026-08-20）**：人工骨架（`codes/jd_annotate/build_jobs.py` 内置 255 个 v1 节点的全量处置表）+ `deepseek-v4-flash` 逐岗阅读数据集真实 JD 样例（每岗 ≤4 条，funtype 挂载匹配 + 标题关键词兜底）生成定义与区分性关键词（共 2,557 个，均值 20/岗；断点缓存 `output/jobs_def_cache.jsonl`）。
- **v2.0 设计原则**：
  1. **类别/岗位两级职责分离**：9 个一级类别（软件开发 33 / 人工智能与数据 19 / 测试与质量 5 / 运维与IT支持 12 / 网络与通信 11 / 硬件与半导体 25 / 安全 4 / 产品与设计 16 / 技术管理 6）为纯组织维度——不挂 funtypes、不进 prompt 标签、不进图节点；二级岗位为唯一实体；
  2. **归类不再依赖 funtype**：逐 JD 内容归类引擎已建（`codes/jd_annotate/classify_job.py`，2026-08-21）——四路信号：岗位名层（标题含岗位名）→ 词库快路（体系 keywords）→ LLM 兜底（batch=20 多标签 1-2 岗，非 IT 域判空）+ **任务/技能向量比对观测信号**（JD 的 0/1 任务/技能向量与基图岗位向量的余弦 top-k，用于后续与 LLM 判定结合：向量差距大 → 新岗位探索线索；亦可观察岗位任务/技能模式漂移）。机制已在 job_2026_1_1.csv 验证（快路 54.1%），全量运行待做；keywords 为 LLM 提案版，泛词精简留待调优；
  3. **低 IT 相关岗位不收录**：无「其它」聚合节点——非 IT 岗位 JD 在逐 JD 归类下自然无岗位（同技术栈空栈口径）。
- **v1 → v2 处置（255 节点全量）**：保留合并 200（相近岗位 14 组合并：售前/售后 8→2、C/C++ 4→1、图像/视觉 4→1、电气 3→1 后剔除、嵌入式 3→1、测试管理层归位等，`source_codes` 可追溯）+ 剔除 46（低 IT 相关：电气/电力、工业自动化、维修、楼宇/安防安装、仪器/计量、消费电子、文职/职能、半导体制造工艺/设备、美工/Flash/多媒体设计；明细见 `jobs_v2.json meta.from_v1.excluded_detail`）+ 纯类别节点退役 9。
- **funtype 兼容口径**：保留域的 v1 funtypes 全量继承 + 漏挂/规范化差异 part 补挂（C/C++开发工程师、技术支持/维护工程师/经理、电气类除外、嵌入式「…/等」变体、电子工程师/技术员、IT经理/IT主管、电路/半导体/网站架构/产品总监/多媒体开发/互联网设计经理等 11 个）；全量 part 频次挂载率 83.8%，未挂部分全部属剔除域或非 IT part（电气/质量/维修/职能等，已逐条核对）。
- **v1 存档**：`classify/Jobs/jobs0806.json`（255 节点）与 `docs/job_classification.json`（带 mapping_log 溯源）保留不动；**运行时基准已切换到 v2**（2026-08-22：`taxonomy_base.json` jobs → jobs_v2.json，extractor 提及识别（load_jobs level=category）/ builder 体系映射与转正（GJ- 写 v2 结构）/ graph 基图岗位节点与 funtype 映射全部跟随单一开关；jobs0806.json 仅作存档，promotion 兼容双结构写入）。全量归类运行与基于归类结果的采样收紧仍待做。
